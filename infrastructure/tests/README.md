# Terraform validation evidence

This directory contains the canonical Terraform test suite for the Catalyst infrastructure modules and a regenerable validation-evidence bundle under `validation-evidence/`.

## Test files

Each `.tftest.hcl` file targets one module (or the composite product graph) and uses `command = plan` runs with `assert` blocks that lock the module's contract:

| File | Module under test | Coverage |
|---|---|---|
| `network.tftest.hcl` | `modules/network` | VPC + public/private subnets + NAT/IGW/route tables |
| `security_groups.tftest.hcl` | `modules/security-groups` | private vs public-alb mode, validation rejection, data-tier ingress |
| `ecr.tftest.hcl` | `modules/ecr` | scan-on-push, lifecycle policy, SSM publishing |
| `ecs_alb.tftest.hcl` | `modules/ecs-alb` | ALB shape, target group health check, SSM publishing |
| `dynamodb.tftest.hcl` | `modules/dynamodb` | PK/SK schema, PITR, TTL, SSM publishing |
| `iam.tftest.hcl` | `modules/iam` | global RBAC groups, OIDC roles, scoped delimiter |
| `lambda_service.tftest.hcl` | `modules/lambda-service` | image packaging, ALB permission, SSM publishing |
| `network_firewall.tftest.hcl` | `modules/network-firewall` | compliance toggle (off → no-op, on → resources) |
| `terraform_backend.tftest.hcl` | `modules/terraform-backend` | KMS rotation, public-access block, lock table |
| `composite_product.tftest.hcl` | `modules/composite/catalyst-product` | full product graph plans with firewall on and off |

## Running locally

The tests run against the AWS provider in plan-only mode and never call AWS. Set fake credentials so the provider initialises:

```powershell
$env:AWS_ACCESS_KEY_ID = "AKIATESTTESTTESTTEST"
$env:AWS_SECRET_ACCESS_KEY = "TESTTESTTESTTESTTESTTESTTESTTESTTESTTEST"
$env:AWS_REGION = "us-west-2"

terraform -chdir=infrastructure init -backend=false
terraform -chdir=infrastructure fmt -recursive -check
terraform -chdir=infrastructure validate
terraform -chdir=infrastructure test
```

```bash
export AWS_ACCESS_KEY_ID=AKIATESTTESTTESTTEST
export AWS_SECRET_ACCESS_KEY=TESTTESTTESTTESTTESTTESTTESTTESTTESTTEST
export AWS_REGION=us-west-2

terraform -chdir=infrastructure init -backend=false
terraform -chdir=infrastructure fmt -recursive -check
terraform -chdir=infrastructure validate
terraform -chdir=infrastructure test
```

The current evidence bundle (`validation-evidence/`) was captured from a clean run of those four commands and is regenerated by Workstream B's CI smoke job. `terraform-test.txt` shows the canonical `Success! 18 passed, 0 failed.` line.
